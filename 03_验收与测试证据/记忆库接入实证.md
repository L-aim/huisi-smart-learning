# AgentArts 记忆库接入实证：跨会话薄弱点召回

> 2026-10-17 实测。三份原始输出按时间顺序排列，均可复现。
> 关键点：`memory-2` 是**全新会话**，会话历史为空；它能说出 include / extend，只可能来自平台记忆库。

## 一、平台侧：抽取与检索（`setup_memory.py`）

```text
STATUS            ACTIVE
UPDATE_OK
EXTRACT_ENABLED   True
EXTRACT_IDLE      30
SESSION_OK        memory-smoke-2
ADD_OK
WAITING 45s 等待记忆抽取……
SEARCH_TOTAL 4    RESULTS 4

```

含义：写入 4 条对话消息（`memory-smoke-1` 2 条 + `memory-smoke-2` 2 条），平台按 30 秒空闲阈值抽取成 **4 条结构化记忆**，语义检索可以取回。

## 三、写入端：`-s memory-1`（第 1 轮对话）

用户输入：

```text
学生 demo，我最容易搞混的是用例图里的 include 和 extend，帮我记一下重点区别。
```

智能体回复（节选，原文未删改）：

```text
[角色: 知识检索]（单点问题，按意图直接走知识检索，不跑全链路）

**结论先说**：本次在学生 demo 的资料库里检索了「用例图 include 与 extend 的区别」，
命中的都是「软件需求分析与建模」系列资源，但返回的引用片段里没有直接给出 include / extend 的区别，
所以我不能把资料库没写的内容当作「资料库结论」给你。

说明：以上 3 条是资料库真实返回的引用（含 `resource:` 出处 ID）。
其中**没有一条覆盖 include / extend 的具体区别**，因此这一步我如实报告「检索未命中该知识点细节」。
```

这一轮**没有**提到历史记忆——它选择了知识检索路径。这一现象在文档里如实保留，因为它说明「记忆注入」是软约束，模型可以不引用。

## 五、为什么这算硬证据

| 判据 | 说明 |
| --- | --- |
| 会话隔离 | `memory-2` 是首次使用的会话名，`get_last_k_messages` 对它返回空，会话历史无法提供回答内容 |
| 字段级复述 | 回复内容与平台返回的 `content` JSON 三段（`context` / `preference` / `categories`）逐字对应，不是概括 |
| 自述未调工具 | 明确写「未调用任何工具」，排除了「现查一次资料库」这条替代路径 |
| 时间可对齐 | 记忆在 18:22–18:26 写入，`memory-2` 在 19:15 提问，中间只可能有平台抽取，不可能有其它写入者 |

## 六、复现命令

```bash
# 1. 建空间并开启抽取（首次）
cd ~/ref/code_new
python create_memory_space.py     # 打印 SPACE_ID / API_KEY，写入 ~/.memory_env
python setup_memory.py            # 等 ACTIVE、开抽取、写两条、45 秒后检索

# 2. 写入一轮对话
~/agentarts/bin/agentarts invoke --agent ict-career-agent -s memory-1 \
  '{"message": "学生 demo，我最容易搞混的是用例图里的 include 和 extend，帮我记一下重点区别。"}'

# 3. 等约 40 秒（空闲抽取），换全新会话追问
~/agentarts/bin/agentarts invoke --agent ict-career-agent -s memory-2 \
  '{"message": "先不要调用任何工具。只根据你的历史记忆回答：我之前说过自己哪里薄弱？把你读到的那条记忆原样复述出来，如果什么都没读到就直说没读到。"}'
```

判据：第 3 步的回复出现 `context` / `preference` / `categories` 三段，即为跨会话召回成立。
