# 演示截图拍摄脚本（5 张必拍）

环境已在 2026-10-19 22:5x 实测拉起：后端 `127.0.0.1:8012`、静态代理 `127.0.0.1:5173`（serve `.\ref\fe_build\dist`）。
**下文每条都在当前环境验证过**：页面能开、接口 200、要拍的字段确有数据。

## 0. 拍之前：环境自检（30 秒）

浏览器打开 `http://127.0.0.1:5173/`，能出首页即通过。若打不开，按顺序起两个进程：

```powershell
# ① 后端（PYTHONPATH 必须含 ICT 根目录，否则编排接口报 MULTI_AGENT_REGISTRY_UNAVAILABLE）
$env:PYTHONPATH='.;01_主工程;01_主工程\backend;.\ref\pylibs3;.\.mcp-deps'
cd '01_主工程\backend'
& 'python' -m uvicorn app.main:app --host 127.0.0.1 --port 8012

# ② 前端静态代理（另开一个窗口）
& 'python' .\_demo_web.py
```

自检命令（都应 200）：`http://127.0.0.1:8012/api/health`、`http://127.0.0.1:8012/api/profile/demo/overview`、`http://127.0.0.1:8012/api/path/overview?student_id=demo`。

**浏览器统一设置**：窗口宽度 ≥1920（F11 全屏更好）、缩放 100%、关掉书签栏与所有扩展图标、关掉 DevTools。深色工具栏会入镜，先收干净。

## 1. `01_总控首页.png` — 首页 `/`

**操作**：直接打开 `http://127.0.0.1:5173/`，等首屏动画停（约 2 秒），不要再滚动。

**必须清晰可见**（判定标准，缺一条重拍）：
- 主标题「为每一位学生，生成专属学习路径。」
- 页面里的「当前学生 demo」类提示（证明演示数据是 demo 口径，不是伪装真实学生）
- 六维画像卡片（学习风格 / 知识基础 / 目标方向 等维度名 + 数值条）

**常见失败**：首屏进得太快只截到骨架屏 → 停 2 秒再拍。

---

## 2. `02_路径推送.png` — 学习路径 `/path`

**操作**：打开 `http://127.0.0.1:5173/path`，等路径加载完（阶梯图出现节点），**保证右上角「当前推送资源」卡片里有内容**（无内容时滚动前先点一次「替换资源」）。

**必须清晰可见**：
- 「当前掌握度 xx%」+ 环形进度
- 「推荐资源 N 个」
- 三阶段路径节点（至少完整看到当前阶段）
- 右侧「当前推送资源」卡片：资源标题、匹配百分比、推荐理由（点一次「推荐依据」展开）

**接口背书**：本页数据来自 `/api/path/overview`（实测 200，含 has_plan / nodes / branches / progress）。

---

## 3. `03_练习诊断.png` — 练习 `/exercise`

**操作**：打开 `http://127.0.0.1:5173/exercise` → 进入「智能做题 / 训练模式」→ 选一题、**先填答案并提交**（要拍到判分），再截图。

**必须清晰可见**：
- 题干全文
- 提交后的判分结果（正确/错误 + 正确答案）
- 考察点 / 知识点标签

**常见失败**：只拍到作答前的空白题干 → 必须先提交再拍，判分回执才是这张图的价值。

---

## 4. `04_评估进化.png` — 学习评估 `/evaluate`

**操作**：打开 `http://127.0.0.1:5173/evaluate` → 点页面右上「生成智能评估」→ 等结果回填 → 再点「提交进化判定」→ 截图。

**必须清晰可见**：
- 左侧「综合学习指数」分环（xx / 100）+ 「读取 N 条本地证据」
- 右侧「策略进化引擎」五类证据计数（画像 / 掌握 / 练习 / 反馈 …）
- 弱点标签（至少 2 个）+ 关联知识点
- 「后端判定结果」区有内容（不是「点击下方按钮后…」的占位文案）

**接口背书**：`/api/evaluate/overview` 实测返回 score / mastery / accuracy / weak_points / evidence。

## 5. `05_编排可视化.png` — 编排 `/orchestration` ← 最关键的一张

**操作（顺序不能错）**：
1. 打开 `http://127.0.0.1:5173/orchestration`
2. 往下滚到「**真实多进程角色编排**」区块
3. **点该区块的运行按钮**（不点就没有 pid，见下）
4. 等 1 秒，9 行步骤出现后截图；背景保留「Agent 拓扑」和「MCP 工具契约」两块更好

**必须清晰可见**（这张是复现规则的核心证据）：
- 9 行步骤，角色依次为 controller → profile → knowledge → path → diagnose×2 → update → review×2
- 每行的 **pid 互不相同**（实测一次运行：12452 / 16276 / 8652 / 28748 / 29900 / 29900 / 3188 / 5332 / 5332，共 7 个不同进程）
- 顶部「Agent 拓扑」+「MCP 工具契约」区块可见

**为什么必须点按钮**：页面下半区数据来自 `POST /api/orchestration/multi-agent`（实测 success=true、9 步、runtime=multiprocess）。上半区「最近一次九步编排（运行期记录）」读的是 `backend\data\role_pipeline_trace.json`，那份文件已生成（9 步、available=true），但它**不含 pid 字段**——所以 pid 只能来自点按钮那一次。重启后端后需要重点一次。
