## 二、作品定位

**慧思智学平台**是一个面向高校软件工程类课程的 AI 个性化学习智能体：以学习者画像为起点，自动生成分阶段学习路径，按阶段产出讲义与练习并判分，把作答回流成可追溯的掌握度证据，再驱动路径与资源调整。

它不是一个"能聊天的课程问答机器人"，而是**把"课程知识点—岗位能力要求—个人薄弱点"三者对齐并落实到每周动作**的一套系统。

---

## 三、要解决的问题

软件工程类课程的学习者普遍撞上三个断点：

1. **三张图对不上**：课程大纲、目标岗位的能力要求、自己的薄弱点，分属三份材料，没有任何一处把它们对齐。
2. **练完就没了**：做完一套题只拿到对错，不知道"我错在哪一类、下一步补什么"。
3. **证据散落**：答疑记录、作答记录、资源浏览分散在不同系统，学期结束时无法回答"这个学生到底进步了多少"。

我们不做的事同样明确：不做题库搬运，不做通用聊天助手，不用编造的"AI 评分"充当学习效果。

## 四、作品形态

平台共 10 个功能页面（另 1 条 `/settings` 重定向回首页），构成一条主线：

| 页面 | 职责 | 关键实现 |
|---|---|---|
| 总控首页 | 入口与主线导览 | 展示当前学生身份，可一键切换演示数据与自建空间 |
| 用户画像 | 六维学习画像 | 学习节奏、知识基础、认知偏好、易错点、正确率、完整度 |
| 资源工坊 | 多类型资源生成 | 讲义文档、思维导图、题库、拓展阅读、实验案例、视频脚本 |
| 路径推送 | 分阶段学习路径 | 阶段卡片 + 掌握度 + 推送资源与匹配理由 |
| 练习诊断 | 出题、作答、判分 | 按阶段目标出题，判分后即时给正确答案与考察点 |
| 知识中枢 | 知识图谱 | 课程入口→章节→知识点→资源四级图，可检索、可加入路径 |
| 多模态实验室 | 按需生成 | 命中未配置能力时明确说明"未生成、也未写入伪资源" |
| 智能辅导 | 实时音视频答疑 | 未配置时显示"需配置"，不伪造对话 |
| 评估进化 | 学习效果评估 | 五类证据→综合分→诊断结论→行动建议 |
| 编排可视化 | 智能体与工具编排的"证据页" | Agent 拓扑、9 个工具契约、运行期 trace、多进程实测 |

**编排可视化**是这套作品与"作品集式 Demo"的关键区别：它把"智能体怎么想、调了哪个工具、用了几个进程、每步传了什么值"直接摆在页面上，评委不需要相信叙述，只需要看页面。

## 五、智能体设计：1 主控 + 5 角色

### 5.1 角色与工具边界

| 角色 | 工具 | 读/写 | 职责 |
|---|---|---|---|
| 主控 controller | `get_role_competency` | 读 | 只做调度与跨步传值，不生成内容 |
| 画像 profile | `get_student_profile` | 读 | 取六维画像与学习摘要 |
| 知识检索 knowledge | `search_knowledge` | 读 | 课程资料检索，返回出处与相关度 |
| 路径规划 path | `get_project_status` | 读 | 取各阶段状态与当前阶段 ID |
| 诊断教练 diagnose | `get_exercise_session`、`submit_exercise_answer` | 读/写 | 按薄弱点出题、判分并回写 |
| 学习评估 review | `get_wrong_book`、`get_learning_evaluation` | 读 | 错题分组与掌握度评估 |
| 更新 update | `add_learning_branch` | 写 | 在当前阶段下新增知识分支 |

五个业务角色的工具集**互不重叠**，主控没有任何生成类工具——这是刻意的：让"谁调了哪个工具"可被逐条核对。

### 5.2 九步确定性闭环

`画像 → 知识检索 → 路径定位 → 出题 → 判分 → 新增分支 → 错题本 → 学习评估 →（画像更新）`

不指定岗位时跳过主控预取，为 8 步。三处跨步传值由代码固定，不交给模型自由决定：

- 第 3 步检索关键词 = 第 2 步画像里的第一个薄弱点
- 第 5 步判分题号 = 第 4 步本次出题的第一题 ID
- 第 6 步新增分支挂载点 = 第 3 步路径的当前阶段 ID

同一输入三轮实测（会话 `pipe-3`、`pipe-6`、`demo-final`）步序一致、入参逐字一致，唯一差异是新增分支的 ID 后缀。

### 5.3 每一步一个真进程

云端运行时里，确定性执行器把**每一步工具调用交给一个独立子进程**（fork + 管道回传），父进程只做调度与传值。实测一次九步执行起 **9 个进程，pid 互不相同**。这不是把"多智能体"画在图上，而是可以在页面和日志里数出来的。

## 六、工具层：自建 MCP 服务

`ict-mcp-server`（当前 v7）以 Streamable HTTP 暴露 9 个工具，经 AgentArts 网关由智能体自动发现（无需手工登记工具列表）。9 个工具即上表的读 6 写 3。

约定：业务失败返回 `{ok:false, error:{code, message}}`，成功返回 `{ok:true, data:{…}, meta:{…}}`；工具名与参数在 `.\API_CONTRACT_AGENTARTS.md` 有完整契约。

## 七、知识层：三条通道并行

| 通道 | 形态 | 实测 |
|---|---|---|
| 平台向量知识库 | 知识库 `ict-course-kb`（pangu_embedding + pangu_rerank），2 篇自编课程文档（11.8 kB，13 个切片） | 命中测试四问得分 1.00 / 0.99 / 0.96 / 0.05，0.05 那条正确表示"资料里没讲 include 与 extend 的区别" |
| 平台低码问答 | 单智能体 `ict-course-kb-qa` 挂同库，要求"只用检索到的内容、资料没讲就直说" | 三问均给出处，第三问明确拒答 |
| 自建检索 | 高代码通道内置词袋检索 + 教材章节切片 | 「参与者」讲义 0.2979 排第一（题库 0.119 第二）；「include 和 extend」讲义 0.275 排第一 |

**一条重要事实**：AgentArts 平台知识库不对外提供检索 API（控制台无地址/密钥，SDK 无知识库模块），因此高代码智能体只能走"自建检索"，平台库通过"单智能体挂库"这条官方路径使用。我们两条都做了，不假装其中一条不存在。

## 八、模型与资产选择

### 8.1 模型：一律选平台预置服务，不自建推理

| 环节 | 选用的模型 | 为什么选它 |
|---|---|---|
| 对话生成（高代码智能体） | 华为云 MaaS `deepseek-v4-flash`（OpenAI 兼容端点 `api.modelarts-maas.com/openai/v1`） | 免自建推理与运维；与平台其余环节同一模型族，生成与评分口径一致；调用量可核算 |
| 知识向量化 | `pangu_embedding` | 平台原生中文向量模型，教材类中文语料语义稳定，无需另建向量库 |
| 检索精排 | `pangu_rerank` | 13 条切片里能把最相关的一条顶到第一（实测首条 0.98） |
| 评估器判定 | `deepseek-v4-flash` | 与对话模型同族，避免"生成用 A、评分用 B"的口径漂移 |

取舍一句话：我们没有 GPU，语料量（8 章讲义 + 2 篇课程文档、平台库 2 篇 / 13 个切片）也远达不到微调门槛，自建推理与微调都不是这个体量的最优解。把"模型可用性"交给平台，团队精力集中在编排设计与工具契约上。

### 8.2 知识资产

| 资产 | 规模 | 来源与合规 |
|---|---|---|
| 自编讲义《软件需求分析与建模-讲义一》 | 8 章 / 23 个概念 / 44 条关系 | 团队自编，不涉第三方教材版权 |
| 平台向量库 `ict-course-kb` | 2 篇文档 / 13 个切片（11.8 kB） | 团队自编课程文档，真上传、真向量化、真召回 |
| 自建检索语料 | 与平台库同源，按 markdown 标题切章 | 两条通道结论可互相印证 |

### 8.3 演示资产

演示学生 `demo` 是随包打包的演示数据：六维学习画像、40 道练习（21 对 19 错）、三阶段学习路径、99 条学习证据。**未接入任何真实学生数据**——既保证演示可复现，也避免把学生隐私带进提交材料。

### 8.4 明确不采用的技术路线

| 不采用 | 原因 |
|---|---|
| 控制台「多智能体」页签 | 平台 SDK 未提供 handoff / subagent 原语，页签承载不了"每步一个真进程"的编排，故改为运行时内自研进程编排 |
| 平台代码沙箱 | 本作品无代码执行需求，引入只会扩大权限面 |
| 第三方向量数据库 | 平台知识库已覆盖课程语料，另建一套无收益 |

## 九、学习闭环的数据与证据

学习效果由五类证据合成，不做黑箱打分：

| 证据类型 | 来源 | demo 当前值 |
|---|---|---|
| 练习作答 | 判分结果 | 35 条 |
| 知识节点 | 知识图谱掌握度 | 0（口径已修，见下） |
| 资源成果 | 已入库资源 | 6 条 |
| 资源反馈 | 用户行为 | 0 |
| 学习事件 | 画像/路径/辅导/评估事件 | 58 条 |

综合分 39 / 100；知识掌握 10%、迁移应用 40.2、学习投入 100、资源匹配 0、策略稳定 60；证据总数 99，结论置信度"高"。

**一个修过的真实缺陷**：早期"知识掌握"恒为 0，原因是评估只读知识图谱节点，而练习判分把掌握度写进了路径阶段，两套口径没接上。修法是让评估优先读图谱、图谱为空时回退到阶段掌握度，并标注数据来源（`knowledge_graph` / `path_stage` / `none`）。修后同一学生从 0% 变为 10%，同时"关键问题"与"行动建议"随之改变——说明这不是数字装饰，而是真的驱动了下一步动作。

| 平台侧评估 | 评测集 8 条 + 评估器，评估任务 **8/8 成功、均分 0.76**（最低 0.47、最高 1.00、Token 16689） |
| 容器能力体检 | vCPU 2、aarch64、允许 fork（子进程 9ms 起）、并发 7 个 fork 子进程全成功 |

平台评估逐条得分：Sprint Review 详解 1.00；拒绝改写他人画像 1.00；拒绝编造 B 站链接 1.00；参与者与用例 0.92；本周该练什么 0.61；资料没有的内容 0.55；功能需求与非功能需求 0.53；include 与 extend **0.47**。

**0.47 这条最值得说**：它是信息量最大的一条（引用了真实检索分数 0.5175 / 0.3221，给出对比表与行动建议）。评估器按"与参考答案的契合度"打分，回答越超出参考答案范围越容易被扣分——这是**评估口径与"多给一步"策略的张力**，不是回答错了。我们保留这条低分并解释它，而不是把它调好看。

## 十一、工程实现

- **后端**：FastAPI，路由按画像/路径/练习/知识/多模态/评估/编排分层，只读接口 35 个 GET 实测除 1 个合法空态外全部 200。
- **前端**：Vue 3 + TypeScript，`vue-tsc -b` 0 错误、`vite build` 通过；浏览器逐页点检 10 个页面，修掉 8 个真 bug（其中 3 个是"接口失败但界面不说实话"）。
- **诚实降级**：未配置大模型时题库改由本地模板生成并标注"未调用大模型"；视频推荐、语音辅导等未配置能力一律显式声明且不写伪数据。
- **可复现**：仓库内有本地多进程运行时（7 角色真进程，pid 互不相同）、假注册表单测 27 条、真注册表 9 步集成测试，以及云端三轮一致性记录。

## 十二、创新点

1. **确定性编排 + 真子进程**：把"多智能体协作"落成"每步一个进程、三处传值由代码固定"，可数、可核、可复现，而不是提示词里的角色扮演。
2. **双通道知识接入**：平台向量库 + 自建检索并行，并对平台不开放检索 API 这一事实做显式说明。
3. **证据化学习效果**：五类证据合成分数，每个结论可回溯到具体记录；口径不一致时修口径而不是修数字。
4. **诚实即产品能力**：能力缺失时说缺失，未生成时说未生成。这条在演示里会被评委直接看到。

## 十三、应用价值与推广

- **教学场景**：任课教师可用同一套系统把课程目标、岗位要求、学生薄弱点对齐，学期末得到可追溯的过程证据。
- **岗前准备**：把岗位能力矩阵与学生画像逐项对照，输出"差在哪、先补哪个"。
- **可迁移性**：把领域知识库与工具集替换掉，即可迁移到其他工科课程（如数据结构、操作系统）与企业新人培训。

## 十四、边界与待改进（如实说明）

1. 多智能体协作是**在云端运行时内自研实现**，未使用控制台"多智能体"页签（平台 SDK 无 handoff/subagent 原语）；该页签当前为空。
2. Demo 目前运行在本机（`127.0.0.1`），未部署公网；截图与录屏为本机实测。
3. 平台评估的 0.47 低分已解释口径，但"是否应调整参考答案覆盖度"仍需实验，不做结论。
4. 自建检索是词袋余弦，长文档会被长度归一化拉低分数；换向量检索是明确的下一步。
